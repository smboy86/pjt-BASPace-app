## 1. 목적

성윤 측에서 전달한 고객 화면, 관리자 화면, 견적 카테고리 수정사항을 누락 없이 정리하고,
결정이 필요한 항목과 외부 자료 의존성을 분리하여 한 항목씩 개선할 수 있는 작업 목록으로
전환한다.

## 2. 요구사항 정리

### 2.1 고객 기본 인터페이스

#### 브랜드와 UI/UX

- 앱 전반의 메인 컬러를 네이비 계열로 변경해 신뢰감 있는 브랜드 인상을 제공한다.
- 고객 하단 내비게이션은 `견적요청 → 나의견적 → 홈 → 알림 → 설정` 순서의 5개 탭으로
  구성하고, 가운데 홈은 탭 바 위로 돌출된 원형 버튼으로 표시한다. 무신사 앱의 중앙 홈
  배치는 참고 사례이며 Safe Area와 접근성 기준을 함께 적용한다.
- 별도 고객 홈은 이미지 중심의 랜딩 화면으로 구성한다.
- 홈의 메인 비주얼 이미지와 서비스 안내 문구는 성윤 측 제공 자료를 사용한다.
- 고객 로그인과 세션 복원 완료 후 기본 진입 화면은 홈으로 변경한다.
- Android에서 견적요청·나의견적·알림·설정의 탭 최상위 화면에서 뒤로가기를 누르면 홈으로
  이동한다. 상세·입력 화면은 직전 화면으로 돌아가고 이력이 없으면 홈으로 이동한다.
- Android 홈에서 첫 뒤로가기는 종료 안내를 표시하고, 2초 이내 두 번째 뒤로가기에서 앱을
  종료한다. 다른 탭에서 홈으로 이동한 입력은 종료 첫 입력으로 계산하지 않는다.

#### SNS 회원가입과 인증

- Google 로그인·회원가입을 우선 지원한다.
- 다른 SNS 공급자는 개발 소요 시간과 운영 필요성을 검토한 뒤 후속 범위로 결정한다.
- 기존 이메일 로그인·회원가입의 유지 여부와 Google 계정의 기존 고객 계정 연결 정책은
  구현 전에 확정한다.

### 2.2 욕실 공사 옵션과 프로세스

#### 시공 타입

- 견적 요청의 최상단에 `철거`와 `덧방` 선택을 배치한다.
- 두 값 중 하나를 반드시 선택하는 단일 선택 UI로 제공한다.
- 타일 선택과 무관한 공사 전체 상위 조건으로 저장한다. `철거`는 기존
  `requires_demolition = true`, `덧방`은 `false`에 대응한다.
- `철거`를 선택하면 관리자가 설정한 시공 타입 추가 비용을 견적에 포함한다. `덧방`은 추가
  비용 없이 시공 타입만 표시한다.
- 철거 추가 비용의 기본값은 `150만원`이며 DB의 설정값과 요청 스냅샷에는 만원 단위 정수
  `150`으로 저장한다.
- 관리자는 `견적 옵션 관리` 목록 최상단의 별도 `시공 타입 금액 설정` 항목에서 철거 추가
  비용을 수정한다. 변경된 설정은 이후 제출되는 요청에만 적용하고 요청 제출 당시 금액을
  스냅샷으로 보존한다.

#### 용어·카테고리·일정

- 기존 `수조` 명칭은 `수전`으로 변경한다.
- 견적 선택 항목에 `줄눈`을 추가한다.
- 고객이 선택한 공사 희망 날짜를 관리자가 추후 수정할 수 있게 한다.
- 고객은 캘린더에서 오늘 이후의 정확한 날짜 하나를 선택하고 `YYYY-MM-DD`로 저장한다.
- 관리자는 변경 사유 입력 없이 날짜를 직접 수정할 수 있다. 원래 날짜, 변경 날짜, 변경
  관리자와 변경 시각은 자동 기록하고 고객 화면에 변경 안내를 표시한다.
- 일정 변경 인앱 알림은 알림 기능 구현 시 연결하며 푸시 알림은 후속 범위다.

### 2.3 관리자 화면

| 영역 | 접수 내용 | 처리 상태 |
|---|---|---|
| 견적 관리 | 견적서 누락 제보 | 오류가 아닌 것으로 확인되어 작업 취소 |
| 업체 관리 | 기존 업체 관리 사양과 기능을 유지한다. | 변경 없음·회귀 검증 대상 |
| 견적 옵션 수정 | 수정 후 저장되지 않는다는 요청 | 오류가 아닌 것으로 확인되어 작업 취소 |

`견적 옵션 수정` 저장 건은 새 수정 작업을 만들지 않는다. 다만 다른 견적 옵션 변경 후 기존
저장 기능이 깨지지 않았는지는 회귀 테스트한다.

`견적서 누락` 제보도 오류가 아닌 것으로 확인하여 별도 진단·수정 작업을 진행하지 않는다.
향후 카테고리·철거 추가 비용 변경에 대한 일반 견적 산출 검증은 종합 QA에서 수행한다.

### 2.4 고객 선택용 견적 상세 카테고리

최종 목표는 다음 8개 상위 항목이다.

| 순서 | 고객 노출 카테고리 | 세부 요구사항 |
|---:|---|---|
| 1 | 타일 | 타일 이미지 확대 기능 포함 |
| 2 | 세면대 / 양변기 | 제품 선택 |
| 3 | 수전 / 유가 | 기존 `수조` 용어 교체 및 유가 범위 포함 |
| 4 | 욕조 | 제품 선택 |
| 5 | 젠다이 / 조적 파티션 | 기존 분리 항목의 통합 여부 검토 후 반영 |
| 6 | 천장재 / 조명 / 환풍기 | 기존 천장·간접등과 신규 환풍기 범위의 통합 여부 검토 후 반영 |
| 7 | 줄눈 | 신규 카테고리 |
| 8 | 욕실장 | 제품 선택 |

원격 카탈로그는 목표 8개 마스터로 전환됐다. 유지 코드 4개의 기존 제품은 보존했고 신규 코드
4개는 제품이 없는 상태로 생성했다. 기존 5개 코드와 연결 제품은 private 백업을 남긴 뒤
삭제했으며, 요청·선택 스냅샷·견적 업무 데이터는 유지했다.

### 2.5 성윤 측 수급 필요 자료

| 자료 | 사용 위치 | 자료 수급 전 처리 |
|---|---|---|
| 최종 견적서 아웃풋 샘플 | 고객 제공 견적서 레이아웃·출력 양식 | 출력 기능과 필드 매핑 확정 보류 |
| 홈 메인 이미지 | 고객 홈 메인 비주얼 | 자리표시자 규격만 정의 가능 |
| 홈 서비스 설명 문구 | 고객 홈 안내 콘텐츠 | 최종 카피 반영 보류 |

시공 타입 추가 비용은 기본 `150만원`, 만원 단위 입력·저장, 관리자 전역 설정과 요청 제출
시점 스냅샷 방식으로 확정했다.

## 5. 권장 진행 순서

`Phase 0 → Phase 1 → Phase 2 → Phase 3 → Phase 4 → Phase 5 → Phase 6 → Phase 7 → Phase 8 → Phase 9 → Phase 10`

고객 홈·내비게이션을 첫 구현 단계로 진행한다. Phase 1 착수 전 홈 이미지와 설명 문구를
수급하며, 수급이 지연되면 라우트·탭·뒤로가기 계약부터 구현하고 임시 콘텐츠는 운영 콘텐츠로
간주하지 않는다. Phase 2 견적 누락 진단은 취소되었으므로 건너뛰고 카테고리·산출 로직을
순서대로 처리한다. 최종 견적서 출력은 샘플과 새 카테고리·철거 추가 비용이 확정된 뒤 진행한다.
