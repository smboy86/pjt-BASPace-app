# 견적 생성부터 시공 완료까지 테스트 시나리오

## 1. 목적

고객 견적 생성부터 관리자 가격 조율, 고객 확인, 업체 배정, 업체 진행 승인과 시공 완료까지
역할별 상태 전이와 접근 권한이 정상적으로 동작하는지 검증한다.

## 2. 사전 조건

- 고객, 관리자, 승인된 업체 담당자 계정이 각각 준비되어 있다.
- 업체 담당자는 승인된 업체의 활성 구성원이며 견적 배정 대상이다.
- 고객·관리자·업체 담당자는 서로 다른 로그인 세션에서 테스트한다.
- 테스트 시작 시 새 고객 견적을 생성할 수 있다.

## 3. 기준 상태 흐름

```text
고객 견적 생성
submitted
→ 관리자 가격 조율
quote_adjustment
→ 고객 조정 견적 확인
quote_adjustment + adjustment_confirmed_at
→ 관리자 업체 배정
matched + assignment assigned
→ 업체 견적 확인 및 진행
in_consultation + assignment accepted
→ 업체 또는 관리자 시공 완료
closed + assignment accepted
```

## 4. 정상 흐름 시나리오

| 단계 | 역할   | 수행 내용                                                                       | 기대 결과                                                                                                      |
| ---- | ------ | ------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| 1    | 고객   | 견적 요청 필수값과 제품을 선택해 제출한다.                                      | 요청이 `submitted`로 저장되고 고객 나의 견적과 관리자 신규 견적에 표시된다.                                    |
| 2    | 관리자 | 신규 견적 상세에서 가격을 입력하고 `견적 조정`을 누른다.                        | 조정 금액이 저장되고 요청이 `quote_adjustment`로 변경된다.                                                     |
| 3    | 고객   | 해당 견적 상세에서 조정 금액을 확인하고 `조정 견적 최종 확정`을 누른다.         | `adjustment_confirmed_at`이 저장되고 확인 완료 상태가 표시된다.                                                |
| 4    | 관리자 | 조정 견적 상세에서 승인 업체를 선택해 배정한다.                                 | 배정이 `assigned`, 요청이 `matched`가 되고 업체의 `배정 견적` 탭에 표시된다.                                   |
| 5    | 업체   | 배정 견적 상세에서 고객 조건, 제품, 금액과 전체 상담 타임라인을 확인한다.       | 고객·관리자에게 보이는 요청 단위 상담 메시지가 업체에도 같은 순서로 표시된다.                                  |
| 6    | 업체   | `견적 확인 및 진행`을 누른다.                                                   | 배정이 `accepted`, 요청이 `in_consultation`으로 변경되고 업체 `시공중 견적`, 관리자 `견적 진행` 탭에 표시된다. |
| 7A   | 업체   | 시공중 견적 상세에서 `시공 완료`를 누른다.                                      | 요청이 `closed`로 변경되고 버튼이 사라지며 업체 `완료 견적`, 관리자 `완료·종료` 탭에 표시된다.                 |
| 7B   | 관리자 | 별도 테스트 견적을 `in_consultation`으로 만든 뒤 상세에서 `시공 완료`를 누른다. | 요청이 `closed`로 변경되고 버튼이 사라지며 업체 `완료 견적`, 관리자 `완료·종료` 탭에 표시된다.                 |

`7A`와 `7B`는 완료 처리 주체별로 각각 독립된 견적을 사용한다.

## 5. 버튼 노출과 상태 검증

| 역할·상태                                       | `시공 완료` 버튼 |
| ----------------------------------------------- | ---------------- |
| 업체, 배정 `accepted` + 요청 `in_consultation`  | 표시             |
| 업체, 배정 `accepted` + 요청 `final_quote_sent` | 표시             |
| 관리자, 요청 `in_consultation`                  | 표시             |
| 관리자, 요청 `final_quote_sent`                 | 표시             |
| 고객 전체 상태                                  | 미표시           |
| 업체 배정 `assigned` 또는 `declined`            | 미표시           |
| 요청 `submitted`, `quote_adjustment`, `matched` | 미표시           |
| 요청 `confirmed`, `closed`, `cancelled`         | 미표시           |

## 6. 오류·권한·중복 요청 시나리오

| 시나리오                                        | 기대 결과                                                                   |
| ----------------------------------------------- | --------------------------------------------------------------------------- |
| 배정되지 않은 업체가 완료 RPC를 호출            | 권한 오류가 발생하고 요청 상태는 변경되지 않는다.                           |
| 배정 상태가 `assigned`인 업체가 완료 RPC를 호출 | 권한 오류가 발생하고 요청 상태는 변경되지 않는다.                           |
| 고객이 완료 RPC를 호출                          | 권한 오류가 발생하고 요청 상태는 변경되지 않는다.                           |
| `matched` 요청에 완료 RPC를 호출                | 상태 오류가 발생하고 요청 상태는 변경되지 않는다.                           |
| 이미 `closed`인 요청에 완료 RPC를 다시 호출     | 중복 완료가 거부되고 `closed` 상태를 유지한다.                              |
| 완료 요청 중 네트워크 오류 발생                 | 버튼 로딩이 종료되고 오류 안내와 재시도 가능한 상태가 표시된다.             |
| 업체와 관리자가 거의 동시에 완료 요청           | 먼저 잠금을 획득한 요청만 성공하고 이후 요청은 현재 상태 검증에서 거부된다. |

## 7. 회귀 검증

- 업체 `견적 확인 및 진행`과 `진행 불가` 동작이 기존과 동일하다.
- 고객·관리자·배정 업체의 상담 타임라인 조회가 유지된다.
- 관리자 가격 조정은 `submitted`에서만 가능하다.
- 고객 조정 견적 확인 전에는 업체 배정을 진행할 수 없다.
- 완료 처리 후 배정 상태는 `accepted`로 유지되고 요청 상태만 `closed`로 변경된다.
- 취소 견적은 `cancelled`, 시공 완료 견적은 `closed`로 구분된다.
