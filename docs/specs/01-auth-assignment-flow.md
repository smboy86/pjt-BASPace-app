# 인증 및 업체 담당자 배정 화면 스펙

## 목적

Supabase 연결 상태와 무관하게 인증 및 업체 담당자 배정의 화면·내비게이션을 먼저
검증한다. 프로토타입에서 입력한 인증 정보와 배정 결과는 서버에 저장하지 않으며, 실제
연결 단계에서 화면의 최종 동작만 feature repository 호출로 교체한다.

## 인증 정책

| 구분 | 정책 |
|---|---|
| 고객 | 이메일 자가가입 사용 |
| 이메일 확인 | 필수 |
| 업체 담당자 | 관리자 초대 전용 |
| 관리자 | 운영자가 직접 등록 |
| 휴대폰 인증 | 사용 안 함 |
| Google/Apple 로그인 | 사용 안 함 |

역할은 `customer`, `partner_staff`, `admin`을 사용한다. 업체 담당자 한 명은 하나의
업체에만 소속되고, 관리자는 견적 요청에 업체뿐 아니라 해당 업체의 특정 담당자까지
지정한다.

## 데이터 정책

- 사진은 선택 입력이며 최대 5장까지 첨부한다.
- 파일당 최대 크기는 10MB이다.
- JPG, PNG, HEIC 형식만 허용한다.
- 회원 탈퇴 시 개인정보와 인증 식별자는 제거하고 견적 기록은 익명화하여 보존한다.

## 화면 플로우

### 고객 인증

```text
로그인
  → 고객 회원가입
  → 이름·이메일·비밀번호·필수 동의 입력
  → 이메일 확인 안내
  → 확인 후 로그인 복귀
```

업체 담당자와 관리자는 공개 회원가입 CTA를 제공하지 않는다. 로그인 화면에서 초대 기반
계정이라는 정책을 안내한다.

### 관리자 배정

```text
운영 현황
  → 배정할 고객 요청 선택
  → 승인된 업체 선택
  → 선택 업체 소속 담당자 선택
  → 배정 내용 검토
  → 완료
```

담당자 선택 목록에는 선택한 업체에 소속된 활성 담당자만 표시한다. 완료 전 검토
화면에서 요청, 업체, 담당자를 함께 확인한다.

## 화면 우선 개발 순서

1. 화면과 역할별 내비게이션을 로컬 프로토타입으로 구현한다.
2. 입력, 로딩, 빈 상태, 오류, 완료 상태를 검증한다.
3. 화면이 필요로 하는 query와 mutation 계약을 feature 단위로 정의한다.
4. Supabase repository를 구현하고 TanStack Query에 연결한다.
5. 성공 시 캐시 무효화와 화면 전환, 실패 시 재시도를 연결한다.
6. `customer`, `partner_staff`, `admin` 실제 계정과 RLS로 통합 검증한다.

## 추후 데이터 연결 계약

### 고객 회원가입

```ts
interface ISignUpCustomerInput {
  name: string;
  email: string;
  password: string;
}
```

성공 결과는 이메일 확인 필요 상태만 반환한다. 이메일 확인 전에는 앱의 고객 세션으로
진입시키지 않는다.

### 담당자 배정

```ts
interface IAssignPartnerStaffInput {
  requestId: string;
  partnerId: string;
  partnerStaffId: string;
}
```

서버는 담당자가 선택 업체에 소속되어 있는지 다시 검증한다. 클라이언트의 목록 필터링만
권한 또는 데이터 무결성 검증으로 사용하지 않는다.

## 현재 프로토타입 범위

- 로그인 폼과 역할별 화면 미리보기
- 고객 회원가입 입력 및 검증
- 이메일 확인·재전송 안내
- 관리자의 4단계 업체 담당자 배정
- 프로토타입 데이터 미저장 안내

실제 이메일 발송, 세션 생성, 초대 수락, 배정 저장, 알림 전송은 Supabase 연결 작업으로
남겨 둔다.
